# 多特征亚像素提取与跟踪工作台设计

## 摘要

构建一个可运行的响应式 Web 原型，支持图片序列、视频和实时相机流。用户在首帧框选并优化 ROI，系统自动推荐圆/圆圈、光斑、十字丝、对角标志、散斑等特征模型，随后逐帧进行亚像素定位和自动跟踪；低置信度或失锁时可人工复核。结果可导出为 CSV、JSON、XLSX、PDF 以及标注图片/视频。

首版采用浏览器本地优先、后端可选精算的混合架构。前端快速路径与 Python 后端共享同一输入/输出契约，目标为 RMS 误差不超过 0.1 px、离线处理至少 30 FPS、实时端到端 P95 延迟不超过 150 ms。

## 架构与数据流

- 客户端层提供任务工作台、首帧 ROI 编辑、参数面板、实时预览、轨迹表、事件时间线和导出入口；桌面三栏布局，平板采用可折叠侧栏与底部指标抽屉。
- 本地处理层使用 CaptureAdapter 统一文件解码和 WebRTC 帧输入；PreprocessWorker 负责灰度化、去噪、背景校正和尺度归一化；TrackerWorker 负责候选检测、ROI 优化、逐帧跟踪和质量评分。
- 后端精算层使用 Python/FastAPI，提供任务提交、批处理、算法复核和报告渲染；可在用户选择或本地能力不足时接管任务。
- 存储与导出层以 IndexedDB 保存原型项目数据；后端任务通过对象存储抽象管理大文件。所有执行路径输出相同 PointTrack 结构。

数据流：输入源 -> 帧抽样/解码 -> 首帧 ROI -> 模型推荐/选择 -> 亚像素定位 -> 预测/校正跟踪 -> 质量门控 -> 结果时间线 -> 报告与导出。

## 算法设计

算法核心采用可插拔 FeatureModel 接口，统一实现 `detectInitial(roi)`、`refineSubpixel(patch)`、`track(previous, current, state)` 和 `quality(result)`。

- 圆/圆圈/光斑：局部背景估计和加权质心初始化；圆/环采用径向梯度与 Taubin 圆/椭圆拟合；光斑支持高斯或二阶矩拟合。
- 十字丝/对角标志：按方向梯度提取两组线，使用鲁棒最小二乘拟合，交点作为亚像素位置；对角方向可由结构张量估计。
- 散斑：首帧保存归一化模板和多尺度金字塔；后续用金字塔相位相关/局部相关取得平移初值，再对相关峰做二次曲面亚像素修正，必要时使用局部光流校正。
- 首帧自动提取亮度、边缘、径向对称性、方向性和纹理统计，推荐候选模型；用户可切换模型并锁定参数。只有连续质量门控失败时才允许自动重新推荐。
- 跟踪采用匀速预测（可选卡尔曼滤波）加局部模型匹配/重拟合。每帧输出坐标、可选 z、协方差近似、模型名、置信度、残差、遮挡/失锁状态和处理耗时。
- 置信度低、残差突增、位移超限或 ROI 越界时标记 `suspect`；连续失败达到阈值则暂停并提示重新框选或回退到最近可靠帧。自动修复与人工复核写入事件记录。

## 统一接口

- `TrackingJob`：输入源、帧范围/采样率、ROI、模型类型、参数、执行模式（local/server）、标定信息和导出选项。
- `PointTrack`：帧号/时间戳、`x/y`（可选 `z`）、协方差或置信椭圆、模型类型、残差、质量分数、状态和耗时。
- `TrackingEvent`：初始化、模型切换、低置信度、失锁、重连、人工复核和导出失败等事件。
- `ReportManifest`：任务元数据、统计摘要、图表/媒体资源索引、算法版本和参数快照。

错误分为输入错误、算法错误、运行错误和导出错误；每类错误都保留任务 ID 与原始上下文，并提供重试、重新初始化或切换执行模式等恢复动作。

## 报告与导出

报告包含任务元数据、输入文件/相机信息、标定和算法参数、模型版本、逐帧结果、有效率、RMS/最大残差、速度、失锁次数、平均/P95 延迟、轨迹与残差图、异常帧缩略图和事件时间线。CSV/JSON 用于机器读取，XLSX 用于工程分析，PDF 用于归档，PNG/JPEG 与 MP4/WebM 用于标注证据。

## 测试与验收

- 单元测试覆盖预处理、各 FeatureModel、亚像素拟合、质量门控和 schema 校验。
- 合成数据覆盖已知亚像素位移、噪声、模糊、亮度变化和遮挡，RMS 目标 <= 0.1 px。
- 端到端测试覆盖图片序列/视频上传、相机模拟流、首帧初始化、失锁恢复及全部导出格式。
- 性能验收为离线 >= 30 FPS、实时端到端 P95 <= 150 ms；大文件切换后端不阻塞界面。
- 兼容性覆盖 Chrome、Edge、Safari 最近两个大版本及桌面/平板视口；报告字段、参数快照和异常事件必须可追溯。

## 假设与范围

- 首版只做响应式 Web，不实现独立原生桌面/移动 SDK；未来通过组件 API 和 WebView 适配。
- 实时相机输入通过浏览器 WebRTC/MediaDevices 抽象接入；具体工业相机驱动不在本期范围。
- 本地与后端算法必须遵守同一 schema 和参数命名，但允许内部实现不同，以便后续将热点算法编译为 WASM。
- 本地项目数据默认保存在 IndexedDB；生产部署可替换为认证、对象存储和任务队列实现。
